### How those prompts apply here

Both prompts were imported from the `cl-mcp` project and describe its environment, not
this one. Where they conflict with this repository, **this file wins**:

- **cl-mcp tools may be unavailable.** `repl-driven-development.md` assumes MCP tools (`repl-eval`, `lisp-edit-form`, `clgrep-search`, `run-tests`, …). No MCP server is configured for this project by default — check whether those tools are actually present before following its shell-command prohibition, and fall back to `Read`/`Edit`/`Grep`/`Bash` when they are not. The underlying **EXPLORE → EXPERIMENT → PERSIST → VERIFY** loop still applies: prototype in a REPL, then persist to `src/`.
- **The test framework is rove**, so `repl-driven-development.md`'s assumption of Rove now holds directly for this project — `rove` and `(rove:run-test ...)` are the real tools, not a mismatch to work around. The `run-tests` tool works normally here, including selective single-test execution: `run-tests {"system": "cl-online-learning-test", "test": "cl-online-learning.test::dense-binary-arow"}` runs just that one `deftest` (REPL equivalent: `(rove:run-test 'cl-online-learning.test::dense-binary-arow)`). This project used to run on prove; the old claim here that cl-mcp's framework auto-detection "does not cover prove" was itself wrong — cl-mcp detects prove fine, but its `:prove` branch was an unimplemented stub that silently fell back to a runner reporting `PASS 0/0` (filed upstream as cl-ai-project/cl-mcp#131). That gap, not a stylistic preference, is why this suite was migrated off prove.
- **Runtime `intern` is intentional here.** `common-lisp-expert.md` forbids runtime `eval`/`intern`, but `clol:train`, `clol:test`, and `function-by-name` dispatch by interning symbol names at runtime — that is the core design (see Architecture). Do not "fix" it.
- **Structs, not CLOS.** `common-lisp-expert.md` is CLOS-protocol-first; every learner here is a `defstruct` generated through macros, for unboxed slot access in hot loops. Keep new learners as structs.
- **Optimization is already measured and committed.** `(optimize (speed 3) (safety 0))` plus exhaustive type declarations are load-bearing in `src/vector.lisp` and every update body, not premature micro-optimization. Preserve them.

The style rules in `common-lisp-expert.md` (Google CL Style Guide, 2-space indent, ≤100
columns, lisp-case naming, `;;;`/`;;`/`;` comment hierarchy) do apply to this codebase.

## Project

`cl-online-learning` (nickname package `clol`) is a Common Lisp library of online linear
learners: Perceptron, AROW, SCW-I, logistic regression (SGD / ADAM) for binary
classification, one-vs-rest / one-vs-one wrappers for multiclass, and RLS for regression.
Every algorithm has a dense and a sparse variant. Dependencies: `cl-libsvm-format`
(dataset parsing) and `cl-store` (model serialization).

## Commands

Load the system:

```lisp
(ql:quickload :cl-online-learning)
```

Run the full test suite (35 `deftest` forms / 96 assertions in `t/cl-online-learning.lisp`):

```sh
ros -Q run --eval '(progn (sb-ext:disable-debugger) (ql:quickload :rove :silent t) (asdf:test-system :cl-online-learning) (sb-ext:quit))'
```

The `(sb-ext:disable-debugger)` is not optional: without it, a failing `test-op` drops SBCL
into the interactive debugger instead of signaling, the debugger then hits EOF on closed
stdin, and the process exits 0 — a green exit for a red suite.

Simpler and correct without that caveat: `./t/run-test.ros` (exits 1 on a red suite, 0 on
green). The CI form is `rove cl-online-learning-test.asd` (requires
`ros install rove cl-store masatoi/cl-libsvm-format`). CI runs on sbcl-bin and ccl-bin ×
ubuntu/macOS.

`t/cl-online-learning.lisp` is 35 `deftest` forms, so a subset can be run directly: the
`run-tests` tool's `test` parameter (e.g.
`run-tests {"system": "cl-online-learning-test", "test": "cl-online-learning.test::dense-binary-arow"}`)
or, from a REPL, `(rove:run-test 'cl-online-learning.test::dense-binary-arow)`.

Command-line tools (roswell scripts in `roswell/`, installed via `ros install masatoi/cl-online-learning`):

```sh
clol-train   [-dim N -n-class N -n-epoch N -type 0|1|2 -sparse 0|1 -mtype 0|1 ...] train-file model-file
clol-predict test-file model-file output-file
```

## Architecture

### Learners are generated by macro, dispatched by symbol name

`define-learner` (src/cl-online-learning.lisp:85) takes only the *update* body and emits
four functions: `<TYPE>-UPDATE`, `<TYPE>-TRAIN`, `<TYPE>-PREDICT`, `<TYPE>-TEST`.
`define-regression-learner` (src/rls.lisp:5) is the analogous macro for regression —
identical except `-PREDICT` returns the raw value instead of its sign, and `-TEST`
reports RMSE instead of accuracy.

Name-based dispatch is load-bearing throughout:

- `clol:train` / `clol:test` do `(intern (concatenate 'string (symbol-name (type-of learner)) "-TRAIN") :cl-online-learning)`. A learner works with them only if the defstruct name exactly matches the generated function prefix.
- `sparse-symbol?` tests whether the type name starts with `SPARSE-`. That prefix decides whether the macro emits `sf`/`sf!` or `f`/`f!` and whether input is declared `sparse-vector` or `(simple-array single-float)`. Renaming a sparse learner without the prefix silently changes generated code.
- `make-one-vs-rest` / `make-one-vs-one` resolve `MAKE-<TYPE>`, `<TYPE>-WEIGHT`, `<TYPE>-BIAS`, `<TYPE>-UPDATE`, `<TYPE>-PREDICT` at runtime via `function-by-name`.

Consequence: a new learner must be a `defstruct` with at least `input-dimension`,
`weight`, and `bias` slots, plus a `%make-<type>` constructor and a public `make-<type>`,
and must be exported from the `:cl-online-learning` package.

### Three vector representations (src/vector.lisp)

The `clol.vector` package operator names encode operand kinds — read the prefix before editing:

| Prefix | Operands |
|---|---|
| `v+`, `v*n`, `dot` | dense × dense |
| `s-v*n` | sparse × scalar |
| `ds-v*`, `ds-dot`, `ds2s-v*` | dense × sparse |
| `dps-v+`, `dps-v*`, `ps-v*n` | dense × *pseudosparse* |

A **pseudosparse vector** is a full-length dense `(simple-array single-float)` that is only
ever read/written at the indices listed in some sparse vector's `index-vector`. Sparse
learners keep their `sigma` / `tmp-vec1` / `tmp-vec2` scratch in this form so an update
stays O(nnz) while the storage stays a plain dense array. This is why sparse learner
structs allocate full `input-dimension` vectors even for 1.3M-dimensional data.

### Performance conventions

- **Everything is `single-float`.** Labels, weights, and parameters are all coerced in the `make-*` constructors. Never introduce a `double-float` — the type declarations under `(optimize (speed 3) (safety 0))` will produce wrong results or crashes, not errors.
- Learner structs preallocate scratch slots (`tmp-vec1`, `tmp-vec2`, `tmp-float`) so update loops cons nothing. `tmp-float` is a 1-element `single-float` array used to avoid boxing a returned float: `f!`, `sf!`, `dot!`, `ds-dot!` write into `(aref result 0)` rather than returning.
- Hot paths declare `(safety 0)`; SCW/ADAM narrow types to `(single-float 0.0)` before `sqrt`. Preserve those declarations when refactoring.

### Label conventions

Binary learners take `±1.0` (single-float). Multiclass learners take an integer class
index `0..K-1`; `clol.utils:read-data` with `:multiclass-p t` produces this by subtracting
1 from the LIBSVM label. `make-one-vs-rest` / `make-one-vs-one` assert `n-class > 2` —
they cannot wrap a 2-class problem.

### Save / restore

`one-vs-rest` and `one-vs-one` cache function objects in struct slots, which `cl-store`
cannot serialize. `clol:save` nulls them (`*-clear-functions-for-store`), stores, then
re-resolves them; `clol:restore` re-resolves after loading. Any new slot holding a
function needs the same treatment in both helper pairs.

## Testing notes

`t/cl-online-learning.lisp` is a **golden-value regression test**: its 35 rove `deftest`
forms carry 96 `ok` assertions that check exact learned weight vectors, biases, and
accuracy figures (within 0.001) for every learner on `t/dataset/a1a` and
`t/dataset/iris.scale`. Any change to an update rule, to float precision, or to iteration
order will break dozens of assertions — the expected values must be regenerated
deliberately, not patched away. Recent history (`single-float-internal` merge and its
follow-up fix commits) is exactly this kind of churn.

RLS / regression is covered: the `regression-rls` deftest (added in commit `adbcd21`)
checks RMSE on `t/dataset/a1a` and the `:stream` output path.
